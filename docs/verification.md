### 로그인 API 배포 경로 보완

사용자 화면에서 로그인 응답을 JSON으로 읽는 중 `Unexpected token 'T', "The page c"...` 오류가 관측되었다. `/api/config`는 정상 응답했지만 운영의 로그인 응답 원문/HTTP 상태는 현재 네트워크 제약으로 직접 확인하지 못했다.

- Node 함수의 파일명 기반 catch-all 대신 `/api/:path*`를 단일 `api/handler.js`로 전달하는 명시적 Vercel rewrite를 사용한다.
- 요청 경로와 조회 필터를 공통 HTTP 라우터에 전달하는 어댑터를 추가했다.
- 재작성된 `/api/auth/login`의 POST 본문, 세션 쿠키, `/api/auth/me` 인증 거부 및 중첩 이력 경로의 필터 보존을 로컬 HTTP 테스트로 확인했다. 로그인 제공자는 해당 테스트에서만 대체한다.
- 브라우저 통합 테스트도 같은 재작성 어댑터를 통과한다.
- 플랫폼의 일반 텍스트 404/HTML 504 응답에는 비밀번호 오류나 JSON 문법 오류 대신 배포 경로/응답 상태 안내를 표시한다.

실제 Vercel 재배포 후 로그인 확인은 별도로 필요하다.

### DB TLS 인증서 설정 보완

운영 로그에 `SELF_SIGNED_CERT_IN_CHAIN`이 보고되어 DB 연결에 공식 CA를 설정하는 `DATABASE_CA_CERT` 변수를 추가했다. 기존 파일 경로 방식도 유지한다.

임시 테스트 CA/서버 인증서로 실제 TLS 핸드셰이크를 실행하여 다음을 검증했다:

- 올바른 CA를 PEM 줄바꿈 또는 `\n` 형태로 등록하면 연결 성공.
- 신뢰할 CA가 없거나 서버 이름이 다르면 연결 거부.
- 잘못된 PEM 입력은 설정 오류로 거부.
- URL의 SSL 우회 옵션은 제거하고 `rejectUnauthorized:true` 유지.
- 로그인 중 인증서 신뢰 오류는 민감한 연결 정보를 노출하지 않고 CA 등록 안내로 응답.

실제 Supabase 프로젝트의 CA 인증서는 아직 제공되지 않았으므로 운영 연결 복구는 미확인이다.

핵심 검증에는 이전 릴리즈 보존·재등장, 부분 파싱의 잘못된 미노출 처리 방지, 한 플랫폼 실패 시 정상 데이터 유지, 재시도·lease 복구·이전 Worker 결과 차단, JSON 재실행 멱등성, 사용자별 접근 제어, 내보내기 수식·HTML 이스케이프가 포함된다.

스크린샷은 `test-results/`에 생성되며 Git에 포함하지 않는다. `dashboard-fixture.png`와 `history-fixture.png`의 데이터는 테스트 전용이다. `production-home.png`는 실제 로컬 프로덕션 서버 화면이다.

  - `itunes.apple.com`
  - `apps.apple.com`
  - `play.google.com`

앱의 연결 상태 확인 결과는 `{"ok":true,"configured":false}`이다. 웹 서버의 동작은 확인했지만 실제 수집 서비스가 운영 준비 완료된 상태는 아니다. 외부 HTML 변경에 따른 파서 호환성도 배포 환경에서 실제 앱으로 검증해야 한다.

## 환경 설정 초안

설치 스크립트, 시작 지침, 필요한 환경 변수 이름을 저장했다. 기존 네트워크 허용목록은 확인할 수 없어 교체하지 않았다. 저장은 현재 실행 환경에 자격증명을 주입하거나 Vercel에 배포하거나 클라우드 환경을 게시한 것이 아니다. 환경 설정에서 값을 입력·저장한 뒤 환경을 게시하고 실제 연결 검증을 이어가야 한다.


## Vercel 직접 수집 전환

- `npm test`: 26개 통과. 기존 대기 작업 처리, 관리자 소유권/Origin/인증, lease 회수, Cron 실제 수집, 실행 예산 종료 후 재개를 검증했다.
