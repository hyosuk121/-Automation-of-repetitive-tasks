브라우저 검증 범위:

- 1440px PC 및 390px 모바일 화면.
- 활성 카드 이동, 준비 중 버튼 비활성화, 방향 버튼 및 키보드 캐러셀.
- 모바일 문서의 가로 넘침 없음.
- 연결되지 않은 환경의 빈 화면과 설정 안내.
- 임시 PostgreSQL을 이용한 등록, 작업 큐 처리, 설명 개정본, 시점별 수치.
- XLSX 다운로드, 경쟁사 수정·보관, 보관된 항목 조회, 수집 실행 이력.
- 테스트 중 발생한 브라우저 예외 없음.

SQL 테스트는 PGlite(PostgreSQL)를 사용하며 실제 서비스 로직과 스키마를 실행한다. 스토어 수집 결과와 인증 사용자는 테스트에서만 주입한다. 운영에 테스트 인증 경로나 샘플 데이터를 넣지 않는다.

핵심 검증에는 이전 릴리즈 보존·재등장, 부분 파싱의 잘못된 미노출 처리 방지, 한 플랫폼 실패 시 정상 데이터 유지, 재시도·lease 복구·이전 Worker 결과 차단, JSON 재실행 멱등성, 사용자별 접근 제어, 내보내기 수식·HTML 이스케이프가 포함된다.

스크린샷은 `test-results/`에 생성되며 Git에 포함하지 않는다. `dashboard-fixture.png`와 `history-fixture.png`의 데이터는 테스트 전용이다. `production-home.png`는 실제 로컬 프로덕션 서버 화면이다.

## 미검증 및 외부 설정 필요

- Supabase Auth 실제 로그인 및 세션 갱신.
- 실제 Supabase DB 마이그레이션과 운영 연결.
- 실제 레거시 소스와의 동작 비교, 사용자 JSON 마이그레이션.
- 공개 Vercel 배포 및 별도 Worker 호스팅.
- 실제 날짜가 바뀌는 운영 환경의 일일 예약 실행.
- Supabase 백업에서 실제 복구.
- 실제 스토어 데이터 수집: 아래 세 도메인에 대한 HTTPS 요청은 현재 클라우드 프록시에서 `403 Forbidden` / `CONNECT tunnel failed`로 거부되었다.
  - `itunes.apple.com`
  - `apps.apple.com`
  - `play.google.com`

앱의 연결 상태 확인 결과는 `{"ok":true,"configured":false}`이다. 웹 서버의 동작은 확인했지만 실제 수집 서비스가 운영 준비 완료된 상태는 아니다. 외부 HTML 변경에 따른 파서 호환성도 배포 환경에서 실제 앱으로 검증해야 한다.

## 환경 설정 초안

설치 스크립트, 시작 지침, 필요한 환경 변수 이름을 저장했다. 기존 네트워크 허용목록은 확인할 수 없어 교체하지 않았다. 저장은 현재 실행 환경에 자격증명을 주입하거나 Vercel에 배포하거나 클라우드 환경을 게시한 것이 아니다. 환경 설정에서 값을 입력·저장한 뒤 환경을 게시하고 실제 연결 검증을 이어가야 한다.
