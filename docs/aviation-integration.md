# 항공 데이터 자동화: 확정 범위와 연동 준비

기준일: 2026-11-20, Asia/Seoul. 이 문서는 구현 계획이며 운영 데이터 연결 완료 보고서가 아니다.

## 확정된 제품 범위

- 홈의 Aircrew Monitoring을 항공 데이터 자동화로 변경한다.
- 공항은 인천공항만 사용한다. 김포·전국 합계는 포함하지 않는다.
- 국제선 출발 여객을 목표 집계 기준으로 한다. 원천의 출발 구분·환승·유무임 포함 조건 확인 전에는 출발 수치라고 표시하지 않는다.
- 조회 목표 기간은 2021년부터 최신 공개월까지다. 미확보 기간은 0이나 추정치로 채우지 않는다.
- 기본 국가는 일본(JP), 베트남(VN), 중국(CN), 대만(TW), 홍콩(HK), 마카오(MO), 태국(TH), 미국(US)이다. 홍콩·마카오는 분리 저장한다. 원천 코드와 내부 코드 사이에 명시적인 매핑이 필요하다.
- 통계·차트는 비로그인 조회 가능. 조회 조건 저장, 관심 국가, 개인 메모는 관리자 전용이다.
- 개인 메모는 조회 조건·기간·분석 근거에 연결한다. 상태 관리와 외부 AI 서비스는 초기 범위에서 제외한다.
- 엑셀 업로드를 정상 운영 과정의 필수 단계로 만들지 않는다. 공식 API 또는 허용된 공식 자동 파일 제공 경로를 검증한다.
- 경쟁사 분석의 기존 데이터·자동 수집·권한은 유지한다.

## 공식 데이터 검증 상태

인계 문서에서 제시한 월간 후보:
https://www.data.go.kr/data/15160910/openapi.do

문서 기준 설명: 인천공항 항공사별 노선별 운송실적, REST JSON/XML, 인증키 필요, 매월 말 전월 실적 제공. 이는 실시간 자료가 아니다.

2026-11-20 이 실행 환경에서 일반 요청과 별도 네트워크 접근 재시도 모두 CONNECT tunnel 403으로 실패했다. 공식 사이트 응답 본문·최신 명세·실제 API 응답은 확보하지 못했다. 이 실패를 제공기관의 자동 수집 금지로 해석하지 않는다.

다음 사항은 아직 미검증이다:

1. 정확한 API 서비스 URL·오퍼레이션·인증키 인코딩 방식
2. 연월 요청 변수 및 2021년 이후 과거 기간 제공 여부
3. 국가·공항·출발/도착·환승·유무임 등 응답 집계 차원
4. 페이지 크기, 페이지네이션, 호출 한도, 오류·빈 결과 구분
5. 출처 표시·이용 조건 및 변경/정정 정책
6. 일별 실적의 별도 공식 자동 연계 경로

위 항목을 추정해서 수집 코드를 만들거나, 월간 API를 일별 데이터로 대체하지 않는다. 최신 월만 제공된다면 이 API 하나로 2021년부터의 자료 확보를 약속할 수 없다.

## 사용자에게 필요한 신청

1. 위 공공데이터포털 링크에서 로그인하고 데이터셋의 제공기관·서비스 설명을 확인한다.
2. `활용신청`으로 개발계정을 신청한다. 신청 목적 예: 인천공항 국가·노선별 여객 실적을 활용한 개인용 여행 시장·계절 패턴 분석 대시보드. 실제 이용 목적에 맞게 작성한다.
3. 신청 상태가 자동승인인지 심의 대상인지 확인한다. 자동승인 또는 승인 소요 기간은 현재 확인되지 않았다.
4. 승인 후 활용신청 상세의 상세기능/참고문서에서 요청 변수·응답 항목·샘플 URL을 확인한다. 명세 파일은 공유할 수 있지만 서비스키가 들어간 URL과 키는 제거한다.
5. 키는 채팅·Git·브라우저 코드에 넣지 않는다. 연동 명세 확인 후 서버 환경 변수 설정을 안내한다. 예정 변수명은 `INCHEON_API_SERVICE_KEY`이며 현재 이 변수를 읽는 수집기는 구현하지 않았다. 아직 변수 등록이나 재배포만으로 수집이 시작되지는 않는다.

## 화면과 계산 규칙

### 시장·계절 패턴

- 시작·종료 연월, 국가 다중 선택, 비교 기준, 조회 적용과 조건 저장.
- 국가 선택은 차트·표 모두에 적용하고, 국가 비중의 분모는 명시한다.
- 월별 여객 추이, 국가별 기간 합계·증감 인원·전년 동기 증감률.
- 전년 동기는 선택 기간 전체를 정확히 1년 이동한다. 각 비교 구간이 완전하지 않으면 증감률을 제공하지 않는다.
- 계절성은 완결된 연도별 월 여객/해당 연도 여객 합계를 계산한 뒤 선택한 완결 연도들의 월별 평균을 사용한다. 필요한 12개월이 없거나 연간 합계가 0이면 제외하고 기준 연도를 표시한다.
- 전년 값 0일 때 증감률은 계산 불가로 표시하고 증감 인원만 제공한다.
- 실제 0, 미공개, 누락, 수집 실패를 구분한다.

### 최근 변화

- 공식 일별 연결이 검증된 후 활성화한다. 미연결일 때 예시 수치를 실제처럼 표시하지 않는다.
- 최근 7일·28일의 끝은 오늘이 아니라 비교 국가들에 공통으로 확보된 최신 완성 실적일이다.
- 실적일과 수집 시각, 공개 지연을 별도로 표시한다.
- 직전 동일 길이의 달력 기간과 비교한다. 일별 자료가 빠졌으면 합계와 비교를 불완전 상태로 표시한다.
- 7일 이동평균은 연속 7일 모두 확보된 경우에만 계산한다.
- 여객 증감은 eSIM 구매 수요나 증가 원인의 확정 근거가 아니다. 관찰 사실과 기획 질문은 분리한다.

## 구현 경계

- 프런트엔드: `/aviation` 경로와 별도 화면 모듈. 기존 `main.js`가 모든 비홈 경로를 경쟁사 화면으로 처리하므로 프로젝트 경로별 렌더링·로딩을 먼저 분리한다. Vercel 재작성 경로도 추가한다.
- 서버: 항공 조회·관리 API 모듈을 분리하고 기존 인증·CSRF/Origin 검사·요청 제한을 재사용한다.
- 공개 응답: 집계 통계와 출처·완성도만 허용한다. 원본 응답, 인증키, 내부 오류, 사용자 ID, 메모·저장 필터는 반환하지 않는다.
- 개인 저장: owner_id를 서버 인증에서 결정한다. 모든 읽기·갱신·삭제에서 소유권을 검사한다. Supabase RLS를 켜고 공개 정책을 임의로 추가하지 않는다.
- 수집: 공식 클라이언트의 타임아웃·오류/할당량 처리·전체 페이지 검증을 갖춘 후 작업 큐로 연결한다. 공식 문서 확인 전 endpoint/응답 필드 이름을 가정하지 않는다.
- 스케줄러: 기존 Supabase Cron의 호출을 재사용하되 항공 큐와 실행 예산을 분리한다. 앱/순위 수집이 항공 과거 적재 때문에 밀리지 않게 한다.
- 배포: 기존 DB 테이블을 재구성하지 않는 추가 마이그레이션. 실측 없는 성능 개선이나 자동 수집 완료를 선언하지 않는다.

## 예정 데이터 모델

정확한 원천 단위 확인 후 확정한다. 특히 원천의 국가 합계와 노선 상세를 같이 더하지 않는다.

| 영역 | 저장 내용 |
|---|---|
| sources | 공식 데이터셋, 버전, 이용 조건, 집계 조건, 월간/일별 |
| ingestion_runs | 확인 시각, 요청 기간, 성공·실패·미공개, 원본 해시/보관 위치, 완성도 |
| observations | 원천 실적 날짜/월, 공항/상대 공항, 국가, 운항 방향, 여객 구분, 원천 차원, 운항·여객 수 |
| corrections | 동일 실적 식별자에 대한 이전 값·새 값·발견 시각 |
| mappings | 원천 코드와 공항·국가 표준 코드 매핑 |
| preferences | 관리자별 관심 국가와 저장 필터 |
| notes | 관리자, 조회 조건, 근거의 원천/기간/계산 버전, 개인 메모 |

동일 실적은 원천·실적 기간·집계 차원으로 고유하게 식별한다. 수집 시각은 실적 식별자가 아니다. 원본이 같으면 확인 로그만 남기고, 수치가 정정되면 정정 이력을 보존하며 관련 계산 캐시를 무효화한다. 불완전한 페이지 결과는 기존 완성 데이터를 덮어쓰지 않는다.

## 실행 순서와 검증

1. 공식 월간 API 신청·명세 확보, 실제 응답 확인.
2. 과거 조회 범위를 검증하고 공식 자동 과거 적재 경로 확정.
3. 검증된 집계 단위로 스키마와 수집기 구현, 작은 기간부터 저장·재실행 검증.
4. 월간 화면·개인 저장 기능·공개/관리자 API 구현.
5. 일별 공식 연계가 확보되면 최근 변화 화면 연결.
6. 원천 대조 합계, 중복/정정, 누락/0, 전년/직전 기간, 완결 연도 계절성, 소유권, 기존 경쟁사 기능 회귀 검증.

현재 완료: 카드 이름/설명 변경과 이 통합 명세. 공식 API 연결·항공 DB·분석 화면·자동 수집은 아직 미구현이며 카드도 비활성 상태를 유지한다.

## 2026-11-20 추가: 제공된 공식 활용가이드 검토와 연결 확인 구현

사용자가 승인 화면과 `항공사별 노선별 운송실적_인천국제공항공사_OpenAPI활용가이드.docx` V1.0(2026-08-10)을 제공했다. 위의 미구현/미검증 목록 중 다음 항목은 이 절로 갱신한다.

- 확정 endpoint: `https://apis.data.go.kr/B551177/operationPerformanceByRoute/getOperationPerformanceByRoute`. 가이드에는 HTTP가 있지만 승인 화면에는 HTTPS가 있으므로 키는 HTTPS로만 전송하며 HTTP 재시도·리디렉션을 하지 않는다.
- 요청: `serviceKey`, `pageNo`, `numOfRows`, `departuresOrArrivals=D`, `regularCode=0/1`, `paxCode=Y`, `type=xml`.
- 과거 연월 파라미터는 명세에 없다. 실제로 반환된 `yearMonth`만 제공 기준월로 사용한다. 서비스 시작일이나 문서 예제 기준월을 데이터 확보 범위로 간주하지 않는다.
- `flightCount`, `totalEff`(유임), `totalNff`(무임), `totalTrf`(환승)를 개별 수치로 취급한다. 환승객과 유임·무임 간 포함 관계가 명확하지 않아 총합을 만들지 않는다.
- 설명에는 국제/국내 구분이 언급되지만 응답 필드 표·샘플에 대응 필드가 없다. 현재 진단 결과를 국제선 전용 통계라고 표시하지 않는다.
- 요청 코드는 D/0/Y, 응답 예제는 출발/정기/여객처럼 한글 값을 사용한다. 수집기는 두 표기를 검증·정규화한다.
- 문서의 ‘실시간(5분)’ 메타정보와 ‘매월 말 전월 실적’ 설명은 모순된다. 월간 사후 실적으로 취급하고 실제 게시 시각은 별도로 관측한다.
- API 응답은 모든 페이지의 전체 건수, 페이지 크기, 행 수, 중복, 식별값을 검증한다. 조회 중 페이지 수가 바뀌거나 부분 응답이면 결과를 집계하지 않는다.

구현된 범위:
- `lib/aviation-source.js`: 공식 XML 응답 기반 클라이언트와 연결 확인. 90초 제한, 최대 각 100페이지, 응답 크기 제한, 키를 포함하지 않는 오류 메시지.
- 관리자 전용 `GET /api/aviation/status`, `POST /api/aviation/inspect`. 기존 인증·Origin 검사와 요청 제한 적용. 확인 요청은 사용자당 분당 최대 2회.
- 홈 항공 카드에서 관리자에게만 `API 연결 확인` 버튼 제공. 기준월, 정기/부정기 전체 건수, 국가 목록, 개별 여객 항목을 확인한다.
- 실제 인증 호출·항공 DB 저장·항공 자동 수집·분석 화면은 아직 완료되지 않았다. 연결 확인은 기존 DB 통계나 스케줄을 변경하지 않는다.

Vercel 설정:
1. 해당 프로젝트 → Settings → Environment Variables.
2. Key: `INCHEON_API_SERVICE_KEY`, Value: 승인된 일반 인증키. Decoding 키가 별도로 제공되면 해당 값을 사용한다. URL에 이미 인코딩된 값도 한 번 정규화한다.
3. Production 환경에 저장하고 새 배포 또는 Redeploy를 실행한다. `VITE_` 접두사를 붙이지 않는다.
4. Ready 후 사이트에서 관리자 로그인 → 홈의 항공 데이터 자동화 카드 → API 연결 확인 → 연결 확인 실행.
5. 키를 제외한 확인 결과의 기준월·건수·오류 메시지를 확인한 뒤 누적 저장·분석 집계 기준을 확정한다. 이 절차만으로 2021년 과거 자료나 일별 데이터가 연결되지는 않는다.
