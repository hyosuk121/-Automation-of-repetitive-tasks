# 2026-10-21: 자동 수집, 과거 자료, 카테고리 순위

## 배포 후 한 번 적용

1. Vercel에서 최신 main 배포가 Ready인지 확인하고 관리자 로그인한다.
2. 왼쪽 **자동 수집 · 과거 기록** → **자동 수집 설정 적용**을 누른다.
   - 새 DB 테이블만 생성하고 기존 스냅샷·경쟁사는 삭제하지 않는다.
   - Vercel의 기존 DATABASE_URL로 Supabase pg_cron, pg_net, supabase_vault를 준비한다.
   - 기존 APP_ORIGIN/CRON_SECRET을 Supabase Vault에 저장하고 private dispatch 함수를 등록한다. 새 비밀번호 입력이나 서비스 가입은 필요하지 않다.
   - `automation-hub-pump`가 5분마다 인증된 POST `/api/cron`을 호출한다. UTC 00:00은 한국 시간 09:00이다.
   - API가 오전 9시 이후 하루 한 번 작업을 생성하고 남은 작업을 계속 처리한다. 수동 수집을 요청한 뒤 웹을 닫아도 다음 호출에서 이어서 처리된다.
3. 5분 뒤 **상태 새로고침**으로 최근 서버 자동 실행 시각을 확인한다. `등록됨`은 호출 성공 증거가 아니므로 최근 실행까지 확인한다.
4. 같은 화면에서 **7월 9일 자료 연결 · 가져오기**를 누르고 앱 연결을 확인한다. 보고서에 앱 ID가 없어 이름/플랫폼이 유일하게 일치하는 항목만 제안한다. 나머지는 직접 연결하거나 건너뛴다.
5. **카테고리 순위**에서 당일 수집 상태를 확인한다. 데이터는 실제 수집을 시작한 날짜부터 쌓인다.

원격 DB/관리 API 인증이 없는 개발 환경에서는 위 버튼 클릭과 운영 검증을 대신 수행할 수 없다. 버튼은 배포된 앱의 기존 서버 환경 변수를 사용한다. Cron 확장 설치 권한이 없으면 Supabase Database → Extensions와 DB 계정 권한을 확인한다. `데이터 저장 준비만 적용`으로 과거 자료 가져오기부터 진행할 수 있다.

## 7월 9일 자료 처리 규칙

- 첨부 자료의 실제 Timestamp는 **2026-07-09 14:05:52 KST**이며 UTC `2026-07-09T05:05:52Z`로 저장한다.
- App Store 12개 / Play Store 12개, App Store 버전 기록 249개를 서버 전용 JSON으로 변환했다. 원본 HTML을 실행하거나 브라우저에 그대로 삽입하지 않는다.
- 스토어 URL/앱 ID가 없어 반드시 현재 등록된 앱에 연결해야 한다. 연결하지 못한 항목을 임의의 경쟁사로 생성하지 않는다.
- 최신 화면은 관측 시각이 가장 최근인 스냅샷을 사용한다. 과거 보고서를 나중에 가져와도 현재 버전·평점·설명이 과거 값으로 바뀌지 않는다.
- 과거 버전은 추가하고, 같은 버전·같은 날짜의 날짜/ISO 시각 표현 차이 때문에 중복 버전을 만들지 않는다. 설명이 다르면 개정본으로 보존한다.
- 보고서 가져오기는 스토어에서 이전 버전이 삭제되었다고 판정하지 않는다. 파일에만 남아 있는 기록도 누적 보존한다.
- 동일 보고서 항목은 관리자별 한 번만 가져온다. 재실행은 건너뛰며 이미 연결한 항목을 다른 앱으로 자동 이동하지 않는다.

## 자동 실행과 운영 확인

Supabase Cron → pg_net → 인증된 Vercel API → Supabase 저장. 브라우저는 필수 실행 주체가 아니다. 기존 Vercel 일일 Cron도 호환되며 날짜 키/lease로 중복 처리를 방지한다.

- 한국 시간 09:00 수집 시작 목표. 외부 서비스 지연 때문에 정각 완료를 보장하지 않는다.
- 수집 호출당 240초 작업 시작 예산, Vercel 함수 300초 제한. Supabase 요청 timeout은 280초다. 실제 Vercel 프로젝트에서 300초 실행 지원을 확인한다.
- 한 호출에서 끝내지 못한 작업은 다음 5분 호출에서 계속한다. 버전/순위 모두 재시도 한도를 둔다.
- 개별 수집 실패와 자동 실행 요청 자체의 실패는 다르다. 버전 수집 이력과 순위 표에서 개별 상태를 확인한다.
- 실패한 날짜의 순위는 다음날 실제 순위로 메우지 않는다. 그 날짜는 실패/미수집 상태를 유지한다.
- 설정의 CRON_SECRET/APP_ORIGIN을 변경했다면 **자동 수집 설정 적용**을 다시 눌러 Vault를 갱신한다.
- 반복 적용은 같은 이름의 Cron을 갱신한다. 비밀값은 cron.job.command에 포함하지 않는다. dispatch 함수는 PUBLIC 실행 권한을 제거한다.

SQL Editor에서 비밀값 없이 확인할 수 있는 명령:

```sql
select jobname, schedule, active from cron.job where jobname='automation-hub-pump';
select started_at, finished_at, status, error_message from public.automation_ticks order by started_at desc limit 10;
select platform, country, chart_day, status, attempts, error_message from public.ranking_runs order by chart_day desc limit 20;
```

호출 로그는 30일 보존한다. 버전/순위 관측 기록은 자동 삭제하지 않는다. 장기간 플랫폼 장애/프로젝트 일시정지/재시도 한도 초과는 수집 실패로 남으며 운영 확인이 필요하다.

## 순위 기준과 표시

- 국가: 대한민국(kr), 무료 인기 차트. App Store iPhone 여행(6003), Google Play 여행 및 지역정보(TRAVEL_AND_LOCAL).
- Apple의 카테고리 RSS, google-play-scraper의 카테고리 TOP_FREE 목록을 사용한다. 검색 결과/추천 목록을 순위로 사용하지 않는다.
- 국가·스토어·날짜별 상위 100개 앱 ID와 순서를 저장하고 등록된 앱 ID로 대조한다. 다른 국가로 등록된 앱은 대한민국 차트 화면에서 제외한다.
- 100개의 고유 ID가 확보된 정상 차트에서만 불일치를 `순위권 밖`으로 표시한다. 일부 목록/중복/네트워크 오류는 `수집 실패`다.
- 그래프는 1위가 위이며 7/30/90일, 플랫폼/경쟁사 필터를 제공한다. 순위권 밖을 101위로 꾸미지 않고 실패/미수집 구간도 선으로 연결하지 않는다. 표에는 실제 수집 시각과 일별 상태를 표시한다.
- 차트에 표시되는 시점은 일별 관측값이다. 앱 자체의 개인화된 추천 화면과 같다고 보장하지 않는다.

## 검증 한계

개발 환경 프록시가 실제 Apple/Google 스토어 연결을 차단한다. 공개 차트의 실시간 반환 형식과 현재 가용성을 운영에서 검증해야 한다. 부족한 데이터는 실패로 표시하며 허위 순위를 생성하지 않는다. Supabase 확장 설치/예약 실행은 운영 권한이 없어 실제 등록을 완료했다고 주장하지 않는다.
