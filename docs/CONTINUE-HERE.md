## 공식 API — 검증된 명세

사용자가 공공데이터포털 활용 신청·승인 완료하고 Vercel 키 설정 후 실제 응답을 받았다.

- 데이터셋: https://www.data.go.kr/data/15160910/openapi.do
- URL: `https://apis.data.go.kr/B551177/operationPerformanceByRoute/getOperationPerformanceByRoute`
- 환경 변수: `INCHEON_API_SERVICE_KEY` (서버 전용, VITE_ 금지)
- 요청: serviceKey, pageNo, numOfRows, departuresOrArrivals=D, regularCode=0/1 각각, paxCode=Y, type=xml.
- 요청 코드와 달리 응답은 출발/정기/부정기/여객 등 한글 값도 사용한다.
- 연월 요청 변수가 없다. 현재 제공 월을 누적하는 API다. 2021년부터 과거 조회가 된다고 가정하지 말 것.
- 월말 전월 실적 제공 설명. 메타정보의 ‘실시간(5분)’과 모순되므로 월간 사후 실적으로 취급.
- 일별 API가 아니다. 최근 변화는 현재 미연결 상태.
- 여객 필드: totalEff 유임, totalNff 무임, totalTrf 환승. 환승 포함 관계 미확정. 세 수치를 합산해 총여객이라고 부르면 안 된다.
- flightCount 운항편수. 0이라도 다른 수치가 있으면 함부로 삭제하지 않는다.
- 설명에는 국제/국내 구분이 있으나 응답 명세에 대응 필드가 없다.
- 키 인코딩 한 번 정규화, HTTPS만 사용, 리디렉션 금지. API 오류 원문/요청 URL에 키가 섞여 노출되지 않도록 주의.

## 남은 개발/검토 — 다음 작업 우선순위

1. 최신 배포에서 검토용 대시보드가 실제 469행으로 어떻게 보이는지 확인. 현재 최신 국가 차트에 대한 실화면 QA는 아직 충분하지 않다. 과거 브라우저 회귀 검증은 주로 기존 기능/항공 진입을 확인했다.
2. UI 개선: 사용자는 설정 방법을 이해하기 어려워했다. 개인 메모가 대시보드보다 먼저 눈에 띄지 않도록 하고, 유효한 확보 월 선택을 쉽게 만든다. 최신 50건만 검색하는 제약 때문에 과거 데이터가 가려질 수 있으므로 서버 기간 조회/페이지네이션 개선 검토.
3. 부분집계를 확정 통계로 오해하지 않도록 배지·제외 내역·필드 정의 확인. 국가 이름 대신 코드 기준 그룹화, 수치 합계 overflow, 응답 범위/누락 필드 검증도 리뷰할 가치가 있다.
4. 개인 기록 브라우저 E2E: 생성·수정·삭제·조건 적용·로그아웃 후 노출 방지. 현재 서버 CRUD 테스트는 있지만 새 개인 UI 전체 상호작용 검증은 제한적이다. 계정 전환 시 모듈 전역의 선택 조건이 남는지 확인.
5. 제공기관 확인이 필요한 항목: URC의 운항편수 0 추가 행 합산 여부/구분 필드, 환승 포함 관계, YCU 국가 코드 누락, 국제/국내 구분.
6. 2021년 이후 과거 월간 자료 공식 자동 연계 및 별도 일별 API 탐색. 현재 API로 해결된 척하지 않는다.
7. 검증된 집계가 확보되면 공개 조회 API, 월간 추이/전년 비교/계절성 히트맵 연결. 원천 응답과 개인 기록은 공개하지 않는다.
